# Реальный контентный кейс и замер времени

Статус на 2026-10-23: протокол подготовлен; результаты отсутствуют. Старый [экономический пилот](PILOT-PROTOCOL.md) сохранён для отдельной проверки решений по SKU. Приоритет перед финалом — производство карточки; изменение цены и рекламы для него не нужно.

## Что нужно от владельца

1. Один реальный товар: исходная карточка/текст и фото, проверенные размеры, материал, комплектность и ограничения. Можно начать с товара из уже подготовленной частной выборки, но пригодность и право показа нужно подтвердить.
2. Реальный отзыв или вопрос по этому товару без имени и контактов покупателя. Если реального отзыва нет, использовать реальный бриф продавца и честно назвать источник брифом.
3. Подтверждение права использовать материалы, передать выбранные факты/фото выбранному AI-провайдеру и показать конкретные обезличенные результаты жюри. Публичная публикация — отдельный выбор; по умолчанию материалы остаются приватными.
4. Продавец/оператор, который обычно делает эту работу: роль, опыт, знание русского и его обычные инструменты; время на две попытки с таймером. Русскоязычный проверяющий для оценки результата по одной рубрике.
5. Если хотим продемонстрировать именно xds.studio — пользователь входит в свой аккаунт и подтверждает доступные кредиты. Пароли и API-ключи в чат не нужны; можно использовать уже доступный внешний инструмент с точным указанием источника.

## Одинаковое задание

Из одной замороженной копии входных данных подготовить русский заголовок, короткое описание, инфографику с подтверждёнными фактами и результат проверки. В ручном процессе использовать обычные инструменты оператора; в assisted — Ops Crew + выбранный внешний инструмент. Зафиксировать фактическую границу помощи, включая обычные AI-инструменты ручного процесса. Один и тот же проверяющий оценивает оба результата по одинаковым правилам; по возможности не показывать ему режим выполнения.

Таймер: отдельно активная работа и полное время до проверенного результата, включая ожидание и исправления. Сохранить исходный/итоговый файл и журнал времени. Не заменять человеческое время длительностью вызова модели. Отметить порядок и эффект повторения: для десяти товаров чередовать, пять начинают вручную и пять с сервисом. Один товар — иллюстративный кейс, не репрезентативное исследование.

## Критерии качества

Факты и единицы точны; нет выдуманных свойств/сертификатов; внешний вид сохранён; русский понятен; текст читаем; права подтверждены. Записать число и смысл исправлений. Если качество не прошло, время попытки всё равно сохранить; не выдавать быстро полученный негодный результат за экономию.

## Запись и отчёт

[Пустая таблица попыток](../templates/content-pilot-attempts.csv), [форма исходных фактов](../templates/content-case-input.json). Хранить заполненное только в приватном runtime, не в Git. Неизвестные расходы/время оставить пустыми; ноль использовать только для реального нуля. Включать отменённые и неудачные попытки. Сопоставлять только завершённые проверенные пары по case_id и одной версии входа; показать каждую пару, число пар, медиану и диапазон разницы `manual − assisted`, качество и ограничения. Отрицательную экономию не удалять. Стоимость подписки распределять только с документированным основанием.

Продуктовый результат: исходник → проверенные факты → текст/изображение → проверка → готовый файл. Публикация на Ozon и рост продаж не требуются для заявления об измеренном времени подготовки. Если заявляем публикацию — отдельно показать реальную карточку и её статус. Если заявляем прибыль — отдельно завершить сравнимые периоды и сверку затрат; без этого писать «эффект на прибыль не измерен».
