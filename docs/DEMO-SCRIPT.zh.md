# 三分钟演示稿

**0:00–0:25 · 问题**
中国跨境卖家不能只看销售额。仓储、广告、汇率和补货周期决定这笔订单到底赚不赚钱。Ozon Ops Crew 把这些因素放进同一个经营控制台。

**0:25–1:00 · 亏损保护**
打开第一件商品。广告前利润为正，但最近三笔交易分摊广告后合计亏损。超过配置上限时，系统给出暂停广告并冻结价格的建议，记录依据。当前是模拟操作，尚未修改真实广告。

**1:00–1:40 · 库存决策**
选择季节商品。低仓储成本时可以等待旺季；提高仓储成本再计算，策略会改变。再查看补货要21天、库存仅够4天的商品，系统建议保护库存而非盲目加广告。

**1:40–2:10 · 商家控制**
进入风控设置，展示店铺默认规则与 SKU 覆盖。调整亏损窗口、广告限额和价格上限。所有建议可解释，模拟动作可追溯。

**2:10–2:35 · 真实连接**
只在本地私密演示时展示 Seller API 目录读取；公开演示不用真实商品数据。采购数据由 Excel 导出 CSV 导入。广告写入尚未接入。

**2:35–3:00 · 验证路径**
今天展示的是工作原型，不宣称已经提升真实利润。下一步用结算数据校准，在影子模式验证，再进行受限对照试点，以广告后利润和库存成本衡量效果。

## 0.3 自动闭环重点
打开“广告自动控制”，点击“运行一次”，展示亏损 SKU 暂停与其他商品预算分配。再次运行展示 no_change（幂等）。修改亏损、库存或全店预算后重新运行，展示不同执行回执。明确说明这是真实可运行的本地模拟执行器，不是已连接的 Ozon 广告账户；每30秒循环仅在标签页打开时工作。

## 0.6 规模化亮点（可选，30 秒）
在“数据与补货”页点击「生成 500 SKU 规模压测组合」，演示全店决策、预测与页面交互在 500 SKU 下保持流畅；打开“评审说明”页展示「价值模型 · 实时计算」——由当前数据经真实引擎即时算出止损保护、仓储敞口与断货风险。说明 10,000 SKU 一轮决策约 28 ms（`node scripts/value-model.mjs` 可复现），规模化路径见 SCALING.md。
