# Конкурсный паспорт

**Ozon Ops Crew** — портал управления прибылью китайского продавца Ozon Global в России. FBO и FBS имеют отдельные затраты; решения по цене и рекламе учитывают запас, будущую поставку и стоимость ожидания.

## Реализовано
Интерактивное демо RU/中文, прозрачная экономика, пять стратегий и ожидание начислений, лимиты магазина/SKU, журнал симуляций, уведомления, CSV импорт/экспорт, локальное чтение реального каталога Seller API.

## Не реализовано
Изменение реальных цен/рекламы, Performance API, импорт реальных продаж/начислений, автоматическая сезонная модель, серверная многопользовательская авторизация и фоновые уведомления. Ключ Seller API проверен чтением каталога; это не подтверждает разрешения на другие методы.

## Экономика
Выручка минус закупка по курсу партии, комиссии, ввоз, исполнение заказа, упаковка, резерв возвратов и распределённая реклама. Сценарное сравнение удержания дополнительно вычитает хранение и стоимость капитала. Налоги и все фактические корректировки должны быть добавлены на этапе сверки реального магазина; текущая модель не является полной бухгалтерской чистой прибылью.

## Принцип остановки
Пользователь подтвердил остановку рекламы и уведомление при суммарном убытке последних продаж с рекламой. Демо проверяет последние N записей с распределённой рекламой после минимального числа завершённых продаж. В production нужен также временной бюджетный предохранитель при нулевых продажах. Возобновление реальной рекламы — только после проверки причины, не по одному удачному заказу.

## Что демонстрировать жюри
1. Убыточный товар: реклама превращает положительную маржу в отрицательный результат.
2. Сезонный товар: хранение до роста спроса выгодно лишь при разумной цене ожидания.
3. Дефицит: реклама сдерживается до прихода новой партии.
4. Залежалый товар: слишком дорогое хранение переводит стратегию в ускорение продаж.

Все четыре сценария синтетические. Не использовать их как доказательство реальной доходности.

## Версия 0.2
Общий бюджет ограничивает сумму рекомендаций SKU; глобальная заморозка сохраняется между посещениями. Учтена реклама без заказов за заданное окно. Добавлены ввод собственных товаров, замена окна продаж из CSV, импорт/экспорт товаров JSON, прогноз по дням с количеством и сроком поставки. Все данные локальные; реальное исполнение Ozon и автоматическое обучение ещё не реализованы.

## Версия 0.6
Воспроизводимая модель ценности (scripts/value-model.mjs, фиксированный сид, реальный движок): портфель 10 000 SKU оценивается за ~28 мс. Документы SCALING.md (мульти-тенант архитектура, стоимость на продавца, репликация на WB / Яндекс Маркет / AliExpress / Temu), VALUE-MODEL.md, COMPLIANCE.md. В ARCHITECTURE.md добавлена таблица контрактов агентов. На странице «Для жюри» — живая панель ценности, считаемая в браузере текущим движком. Кнопка «Портфель 500 SKU» на странице данных показывает масштаб интерфейса. 36 автоматических проверок, включая бенчмарк 2000 SKU и регрессионный тест allowlist сервера.
