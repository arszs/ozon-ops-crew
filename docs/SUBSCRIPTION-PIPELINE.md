# Перенос SKU через подписку Codex · 0.9

## Что работает

Перевод и OCR вызывают установленный `codex exec` с существующим входом через ChatGPT. API-ключ не требуется, OAuth-токены не читаются и не копируются приложением. Вызовы выполняются последовательно, в отдельном временном каталоге, с JSON Schema, режимом read-only, отключёнными shell/browser/apps/hooks и без переменных окружения продавца. Это локальный однопользовательский режим; лимиты подписки действуют, бесконечная пропускная способность не предполагается.

Официальные основы: [Codex non-interactive mode](https://learn.chatgpt.com/docs/non-interactive-mode), [authentication](https://learn.chatgpt.com/docs/auth).

```sh
npm ci
codex login status
npm start
```

В интерфейсе 商品迁移 → **用订阅运行 AI 测试商品** → **运行至人工确认**. Кнопка создаёт синтетический товар с двумя исходными PNG и известными областями текста. Перевод и OCR настоящие; Taobao не запрашивается. Старый DEMO с фиксированным переводом сохранён отдельно. Тестовые товары нельзя направить в реальный магазин.

## Изображения

`adapters/media.mjs`: загрузка PNG/JPEG/WebP → нормализация → Codex vision OCR и RU-перевод → замена текста в явно заданной прямоугольной области с однотонным фоном. Это не универсальный inpainting: сложный фон и неизвестная область требуют ручной обработки. Товар вне указанной области не меняется. MVP обрабатывает первые две картинки, сохраняет исходники и результаты по SHA-256, повторно использует проверенные результаты. Перевод, логотипы, расположение текста и внешний вид проверяются человеком.

Для экспорта поля изображения:

```json
{
  "url": "https://img.alicdn.com/your-image.jpg",
  "width": 900,
  "height": 1200,
  "rightsConfirmed": true,
  "textRegions": [{"x":40,"y":70,"width":800,"height":260,"background":"#f0f2e8"}]
}
```

Координаты задаются для нормализованного изображения. Не копировать пример на неизвестную фотографию. Поддерживается одна область на изображение; если OCR обнаружил текст без области, стадия останавливается. Только `alicdn.com` и домены из серверного `OPS_IMAGE_HOSTS` доступны загрузчику; редиректы, приватные IP и изображения >12 MB блокируются. Альтернатива — POST `/api/workspace/assets` с base64 PNG/JPEG до 1.3 MB и `assetId` в экспорте. Произвольные локальные пути из браузера не принимаются.

Обработанные картинки скачиваются из UI. Перед публикацией их нужно разместить на разрешённом публичном HTTPS-хранилище и указать конечные URL. Приложение само не загружает изображения на внешний хостинг. Ozon не получит localhost-URL.

## Категории и публикация Ozon

- Поиск: `/v1/description-category/tree`.
- Обязательные поля: `/v1/description-category/attribute`.
- Значения: `/v1/description-category/attribute/values` и `/values/search`.
- Оператор выбирает категорию и фактические характеристики. Идентификатор + текст справочного значения проверяются через API. Неизвестные, повторные, отсутствующие обязательные и неподдерживаемые комплексные атрибуты блокируют этап. ТН ВЭД, необходимость маркировки, сертификация и ставка НДС не выдумываются моделью.
- Русское описание должно совпадать с атрибутом «Аннотация». Цена, валюта кабинета, габариты/вес упаковки, конечные изображения и подтверждения прав/проверки вводятся явно.
- В гейте доступен полный фактический JSON запроса. Подтверждение связано с его хешем; изменение настроек или текста отменяет старое согласование.
- После отдельного нажатия исполнения: read-only проверка существующего `offer_id`, затем `/v3/product/import`. Существующие SKU отклоняются: этот сценарий не предназначен для обновления карточек. Операции нужно выполнять из одного экземпляра сервера; независимые внешние изменения между проверкой и запросом исключить невозможно.
- `task_id` означает **submitted**, а не «товар продаётся». Кнопка проверки вызывает `/v1/product/import/info` и читает `statuses` через `/v3/product/info/list`. Imported отображается отдельно от решения модерации. Ошибки сохраняются, неоднозначные отправки автоматически не повторяются.

Методы дерева и характеристик проверены на реальном подключении Ozon. Отправка настоящего товара и прохождение модерации ещё **не проверены**: нет реального экспорта Taobao. Payload/гейты/повторная отправка проверены тестами с контролируемыми HTTP-ответами. WB write-адаптер и реальные операции цены/остатка/ответа остаются отключены.

## Проверенный прогон

12 октября 2026 выполнен один синтетический SKU:

- реальный перевод через подписку: 36.1 с;
- два OCR-вызова и формирование PNG: 58.5 с;
- суммарно машинные стадии: около 95 с; категория в этом прогоне демонстрационная;
- отдельно реальный API вернул категорию «Коробка для хранения» и обязательные атрибуты; они также отобразились в браузере.

Это **не** замер реального Taobao SKU, не время публикации, не доказательство 80% полей без правок. Реальных опубликованных SKU: 0. Денежная стоимость API не рассчитывается: использована подписка, фактические usage-счётчики сохранены в доказательствах.

Далее нужен один реальный экспорт с правами на изображения и проверенными товарными характеристиками. Таобао-аккаунт не нужен для проверки механики на синтетическом примере, но без фактического товара нельзя честно проверить полный бизнес-сценарий.

## Измерения в интерфейсе

В разделе миграции доступен блок «实测证据»: обновление метрик из audit/tool.complete и истории переводов, затем скачивание JSON-сводки. Группы: синтетический AI, фиксированный DEMO, экспорт продавца (происхождение независимо не проверено). Экспорт содержит SKU и внутренние идентификаторы, но не исходные тексты, промпты, секреты или сырые отзывы. Перед публичной демонстрацией проверьте, допустимо ли раскрытие самих идентификаторов.

Машинное время суммирует все успешно завершённые стадии, включая повторы. Время неудачных вызовов, ожидание человека и модерации не входят. Изменения считаются только для двух текстовых полей (название и описание); исправление с последующим возвратом к исходнику всё равно считается правкой. Это не метрика качества всех атрибутов/изображений и не подтверждение цели ≥80%. Сквозное время до продаж, модерация и денежная стоимость остаются неизмеренными.

## AI для сообщений покупателей

В 客户沟通 кнопка AI 翻译并起草 запускает тот же изолированный Codex CLI: перевод RU→ZH и короткий русский ответ. Email/телефоны маскируются до запроса; инструкция запрещает обещания компенсации/замены и запрос личных данных в публичном ответе. Это prompt-ограничение, не гарантия: продавец проверяет текст в отдельном гейте. Исходящий API для реального ответа по-прежнему выключен.

Сохраняются версии, prompt, hashes, provider usage и время. Повторный одновременный запрос объединяется; ответ модели отбрасывается, если исходное сообщение изменилось или уже отвечено. Сама генерация не создаёт операцию и не подтверждает отправку.

Проверен реальный вызов подписки на синтетическом отзыве о треснувшей крышке. Первый вариант запросил номер заказа; после уточнения инструкции повторный вариант направил покупателя в помощь по заказу без обещания замены. Второй вызов: 13.740 с. Это не измерение качества на выборке настоящих отзывов. 96 автоматических тестов проходят.
